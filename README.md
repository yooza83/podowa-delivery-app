# 🍇 포도와농장 배송 루트 최적화 웹앱

포도와농장(유기농 포도 농장)의 택배 배송 업무를 돕는 웹앱입니다.
주문 엑셀을 올리면 지도에 배송지를 표시하고, 지역별로 담당자에게 나눈 뒤,
각자의 최적 배송 순서를 **TMap 경유지 최적화 API**로 계산해 3가지 안으로 비교해줍니다.

- 사용 흐름: **① 엑셀 업로드 → ② 지도 확인·지역별 담당자 배정 → ③ 출발지 확인·경로 3안 비교·확정·엑셀 다운로드**
- 배송 순서는 절대 추측하지 않고, 매번 TMap API가 실시간 교통을 반영해 계산합니다.
- 출발지는 기본적으로 농장 주소를 쓰지만, ③ 화면에서 경로를 계산하기 직전에 **다른 출발지 주소로 바꿔서** 계산할 수도 있습니다(예: 다른 곳에서 출발하는 날).

## 폴더 구조

```
포도와농장-배송앱/
├── frontend/        React + Vite + TypeScript (모바일 우선 UI)
├── backend/         Node + Express (TMap API 키 보호용 프록시, 세션 로그인)
├── sample-data/      테스트용 가짜 주문 엑셀 (git에 커밋됨)
├── local-data/       실제 주문 파일 등 민감한 파일을 둘 때만 사용 (git에서 항상 제외됨)
├── Dockerfile        멀티스테이지 빌드 (프론트+백엔드 한 이미지)
└── docker-compose.yml
```

> ⚠️ **실제 고객정보가 담긴 파일은 절대 `sample-data/`에 두지 마세요.** 그 폴더는 git에
> 커밋되어(지금은 GitHub 비공개 저장소에도 올라가 있음) 항상 가짜 데이터만 있어야 합니다.
> 테스트/분석용으로 실제 파일을 컴퓨터에 잠깐 둬야 한다면 `local-data/` 폴더를 쓰세요 —
> `.gitignore`에 등록돼 있어 실수로 커밋될 일이 없습니다.

## 개인정보 · 보안 설계

- **고객명·연락처는 프론트엔드(브라우저) 메모리에만 존재**하고 백엔드로 절대 전송되지 않습니다.
  백엔드가 받는 것은 딱 두 가지뿐입니다: ① 지오코딩용 **주소 문자열**, ② 경로최적화용 **좌표 + 임시 ID**.
- 업로드한 주문 데이터는 서버에 **저장되지 않습니다**(새로고침하면 사라짐). DB 자체가 없습니다.
- TMap에서 받은 좌표는 서버 메모리에 캐시되지만 `GEOCODE_CACHE_TTL_HOURS`(기본 12시간, 최대 24시간 권장)가
  지나면 자동 폐기됩니다 — TMap 이용약관(좌표/경로 데이터 24시간 초과 보관 금지)을 지키기 위함입니다.
- TMap **REST 키**(지오코딩·경로최적화 호출용, `backend/.env`의 `TMAP_REST_APP_KEY`)는 백엔드에서만 호출합니다. 프론트/네트워크 응답에 절대 노출되지 않습니다.
- TMap **JS 키**(지도 표시용, `frontend/.env`의 `VITE_TMAP_JS_APP_KEY`)는 특성상 브라우저 화면 소스에 그대로 보이는 값입니다 — TMap JS SDK는 원래 `<script src="...?appKey=...">` 형태로 로드하는 방식이라 애초에 숨길 수 없습니다(백엔드를 거쳐 전달해도 최종적으로 브라우저에 그대로 노출됩니다). 가능하다면 대시보드에서 도메인 제한 등 추가 보호 설정을 걸어두세요(존재 여부는 앱 사용 안내를 확인).
- 접근 제어는 가족이 공유하는 비밀번호 1개 + 서버 세션 쿠키(httpOnly)입니다.

## 실제 농장 주문서 그대로 업로드하기

포도와농장에서 실제로 쓰는 주문 엑셀(제목/합계 줄이 섞여 있고, "받는분" 칸에 이름과
전화번호가 같이 적혀 있고, 품목·구역·금액·결제상태 같은 컬럼이 있는 형식)을 그대로
올릴 수 있습니다.

1. **컬럼명(제목) 줄 선택** — 엑셀 맨 위에 제목/설명 줄이 있어도, 실제 "받는분/주소"
   같은 컬럼명이 있는 줄을 자동으로 찾아서 미리 선택해줍니다. 다르면 직접 골라주세요.
2. **이름+전화번호 자동 분리** — "홍길동 010-1234-5678"처럼 한 칸에 같이 있어도 이름과
   전화번호를 자동으로 나눠서 각각 채웁니다.
3. **제목/합계 줄 자동 제외** — 표 중간에 헤더가 또 나오거나(구간이 여러 개), "합계 12건 ·
   박스 총 15개" 같은 요약 줄이 섞여 있어도 자동으로 "제외" 상태로 미리 체크해둡니다.
   업로드 화면에서 표로 다시 확인하고 체크박스로 직접 바꿀 수 있습니다.
4. **품목/구역/금액/결제상태**도 컬럼으로 매핑해두면 지도 화면·최종 배송 순서표·엑셀
   다운로드에 그대로 같이 나옵니다(특히 "착불" 같은 결제상태는 배송 기사님이 현장에서
   금액을 받아야 하는지 바로 알 수 있어 유용합니다).

## 사전 준비물

- Node.js 20 이상
- TMap appKey (앱 1개만 만들어도 되고, 지도용을 분리하고 싶으면 2개) — 아래 [TMap appKey 발급받기](#tmap-appkey-발급받기) 참고
- (선택) Docker

## 로컬 실행

### 1) 환경변수 설정

백엔드용, 프론트엔드용 두 군데에 나눠 설정합니다(TMap JS 키는 프론트 **빌드 타임**에 HTML에
직접 심어야 해서 — 이유는 아래 "알아두어야 할 제한사항"의 지도 로딩 관련 항목 참고).

```bash
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
```

`backend/.env`를 열어 값을 채웁니다.

| 변수 | 설명 |
|---|---|
| `SHARED_PASSWORD` | 가족이 공유해서 쓸 로그인 비밀번호 |
| `SESSION_SECRET` | 아무 랜덤 문자열 (세션 쿠키 서명용) |
| `TMAP_REST_APP_KEY` | TMap 지오코딩·경유지최적화 호출용 키 (비공개, 백엔드 전용) |
| `TMAP_ROUTE_OPT_SIZE` | 경유지 최적화 상품 크기: `10`/`20`/`30`/`100` 중 하나 (기본 `20`). 해당 크기의 상품을 미리 신청해야 함 — 아래 "TMap appKey 발급받기" 참고 |
| `FARM_NAME` / `FARM_ADDRESS` | 배송 출발지(농장) 이름/주소 |
| `GEOCODE_CACHE_TTL_HOURS` | 좌표 캐시 보관 시간(시간 단위, 24 이하 권장) |
| `COOKIE_SECURE` | HTTPS 없이 배포해야 할 때만 `0`으로 설정 (기본은 운영모드에서 자동으로 Secure 쿠키 사용) |

`frontend/.env`를 열어 값을 채웁니다.

| 변수 | 설명 |
|---|---|
| `VITE_TMAP_JS_APP_KEY` | TMap 지도 표시용 키. `backend/.env`의 `TMAP_REST_APP_KEY`와 같은 값을 넣어도 됩니다(앱을 1개만 만든 경우). **프론트를 빌드할 때마다** 이 값이 HTML에 심어지므로, 값을 바꾸면 `npm run build`(또는 `npm run dev`) 를 다시 실행해야 반영됩니다. |

### 2) 설치 & 실행 (개발 모드, 핫리로드)

터미널 2개를 사용합니다.

```bash
# 터미널 1: 백엔드
cd backend
npm install
npm run dev        # http://localhost:4000
```

```bash
# 터미널 2: 프론트엔드
cd frontend
npm install
npm run dev         # http://localhost:5173 (백엔드로 자동 프록시됨)
```

브라우저에서 `http://localhost:5173` 접속 → `SHARED_PASSWORD`로 로그인 →
`sample-data/샘플_주문.xlsx`로 테스트해보세요(전부 가짜 데이터입니다).

### 3) 운영처럼 한 서버로 실행

```bash
cd frontend && npm install && npm run build && cd ..
cd backend && npm install && npm run build && cd ..
cd backend && node dist/server.js   # http://localhost:4000
```

> ⚠️ **로컬(HTTP)에서 테스트할 때는 `NODE_ENV=production`을 붙이지 마세요.**
> 운영 모드는 로그인 쿠키에 `Secure` 속성을 자동으로 붙이는데, `https://`가 아닌
> `http://localhost`에서는 브라우저가 이 쿠키를 저장하지 않아 로그인이 계속 실패합니다.
> 실제 서버(HTTPS 뒤)에 배포할 때만 `NODE_ENV=production`을 붙이세요.
> 그래도 HTTPS 없이 운영 배포해야 하는 특수한 경우엔 `.env`에 `COOKIE_SECURE=0`을 추가하세요.

이 명령을 실행해둔 터미널을 닫으면 서버도 함께 종료됩니다. 계속 켜두고 테스트하려면
터미널을 그대로 열어두거나, `nohup node dist/server.js &` 처럼 백그라운드로 띄우세요.

## Docker로 실행

```bash
docker compose up --build
```

`backend/.env` 파일을 그대로 읽어 사용합니다(`docker-compose.yml`의 `env_file`).
`http://서버주소:4000`으로 접속합니다. **반드시 HTTPS(리버스 프록시 등) 뒤에 배포하세요** —
그래야 로그인 쿠키(Secure)가 정상 동작하고, 가족들이 입력하는 정보도 암호화됩니다.

> ⚠️ `frontend/.env`도 미리 만들어두세요(`docker compose up --build` 실행 전). 프론트는
> Docker 이미지 빌드 단계에서 정적 파일로 완성되는데, 이때 `VITE_TMAP_JS_APP_KEY`가 HTML에
> 심어집니다. 나중에 컨테이너를 재시작해도 반영되지 않고, `docker compose build`로
> **이미지를 다시 빌드해야** 값이 바뀝니다.

## TMap appKey 발급받기

> ℹ️ 2026-09에 openapi.sk.com에서 실제로 회원가입→상품 신청까지 진행해보고 확인한 최신 절차입니다.
> **appKey는 "상품" 단위가 아니라 "앱(App)" 단위로 발급됩니다** — 앱을 하나 만들면 키가 하나 나오고,
> 그 앱에 필요한 상품(지오코딩, 경유지 최적화 등)을 나중에 얼마든지 추가로 신청해 쓸 수 있습니다.
> (참고: SK open API는 2026-10-02부터 "A.Console"로 서비스명이 바뀔 예정이라고 사이트에 공지되어
> 있습니다. 그 이후엔 화면 구성이 달라질 수 있어요.)

1. [openapi.sk.com](https://openapi.sk.com)에서 **회원가입/로그인**합니다.
   - **개인 회원**: 개인 용도로 쓰고 세금계산서가 필요 없으면 이걸로 충분합니다.
   - **사업자 회원**: 포도와농장 명의로 세금계산서를 받아야 한다면 이걸로 가입하세요.
     사업자등록증 전자 사본 업로드가 필요합니다. 개인 회원으로 먼저 가입해도 나중에
     사업자 회원으로 전환할 수 있습니다(단, 전환 후엔 다시 개인 회원으로 못 돌아갑니다).
2. **앱 만들기**: 화면 우측 상단 **대시보드 → 앱 → 앱 만들기**. 이름은 자유롭게
   (예: "포도와농장 배송앱") 정하면 됩니다. 앱을 만드는 즉시 **앱키(appKey)** 가 자동 발급됩니다.
   - 이 앱 하나의 키만으로도 충분히 동작합니다(`backend/.env`의 `TMAP_REST_APP_KEY`와
     `frontend/.env`의 `VITE_TMAP_JS_APP_KEY`에 **같은 키**를 넣어도 됩니다). 다만 JS
     지도 키는 브라우저 화면 소스에 그대로 노출되므로, "지도 표시 전용" 앱을 하나 더
     만들어 키를 분리해두면 더 안전합니다 — 대시보드에 도메인 제한 같은 보호 설정이
     있는지 확인해보고 있다면 그 앱에 적용하세요.
3. **앱키 확인**: 대시보드 → 앱 → 방금 만든 앱 선택 → **앱키(appKey) 탭**에서 값을 복사합니다.
4. **상품 사용 신청**: 홈 화면에서 카테고리(예: 교통/위치 → TMAP)를 고르고, 필요한 상품을
   클릭해 들어가 사용 신청을 진행합니다. 신청할 때 **어느 앱에 포함시킬지 선택**하게 됩니다.
   이 앱이 실제로 쓰는 상품은 다음 두 가지입니다.
   - **Full Text Geocoding** (장소 카테고리) → 주소를 좌표로 변환. Free 요금제 기준
     하루 호출 한도가 넉넉합니다(대시보드 "사용 한도"에서 확인한 실측값: 30만 회/일).
   - **경유지 순서 최적화** (경로 카테고리) → 10/20/30/100개짜리가 **각각 별도 상품**으로
     있고, **Free 요금제의 하루 호출 한도가 상품마다 완전히 다릅니다** — 실제로 확인해보니
     **100개짜리는 하루 딱 1회**, **10·20개짜리는 하루 50회**였습니다(계정/시점에 따라
     달라질 수 있으니 신청 전 대시보드 "사용 한도" 탭에서 다시 확인하세요). 이 앱은
     기본적으로 **20개짜리**를 쓰도록 되어 있으니 **"경유지 순서 최적화 20"을 신청**하세요.
     담당자 한 명당 배송지가 20곳을 자주 넘는다면 30이나 100도 고려하되, 그 상품의
     하루 한도가 실사용에 충분한지 먼저 확인하는 걸 권장합니다.
   - **지도(JS SDK)**: 실제로 확인해보니 지오코딩·경유지최적화만 신청한 상태에서도 같은
     앱의 키로 지도 표시가 바로 됐습니다 — "TMAP" 상품 하나에 지도 기능도 포함되어 있는
     것으로 보입니다. 혹시 안 뜨면 홈 화면의 "지도" 카테고리에서 별도로 신청해보세요.
5. 요금제(무료 Free / 종량제 유료)는 대시보드의 "API 사용 요금" 메뉴 또는
   `skopenapi@sktelecom.com` 문의가 가장 정확합니다(수시로 바뀌므로 이 README보다 우선하세요).
   **Free 요금제는 한도를 넘겨도 자동으로 요금이 청구되지는 않는 것으로 보입니다**(호출이
   막힐 뿐). 확실히 하려면 대시보드의 "요금 조회" 메뉴에 청구 내역이 없는지 확인하세요.
6. 발급받은 키를 `backend/.env`의 `TMAP_REST_APP_KEY`와 `frontend/.env`의
   `VITE_TMAP_JS_APP_KEY`에 넣습니다(2번에서 앱을 하나만 만들었다면 두 곳에 똑같은
   키를 넣으면 됩니다). 신청한 경유지 최적화 상품의 크기를 `backend/.env`의
   `TMAP_ROUTE_OPT_SIZE`에도 맞춰 넣으세요(기본값 `20`).

## 알아두어야 할 제한사항

- **경유지 최적화 상품은 크기(10/20/30/100)에 따라 Free 요금제 하루 호출 한도가 전혀
  다릅니다**(위 "TMap appKey 발급받기" 참고 — 100개짜리는 하루 1회로 사실상 실사용이
  불가능한 수준이었습니다). `.env`의 `TMAP_ROUTE_OPT_SIZE`로 실제 신청한 상품 크기를
  맞춰주세요. 한도를 다 쓰면 "TMap 호출 한도에 도달했습니다" 에러가 뜨고 자동 재시도는
  하지 않습니다(하루 한도라 재시도해도 소용없고, 오히려 한도만 더 깎일 수 있어서입니다) —
  다음 날 다시 시도하거나 더 넉넉한 상품으로 바꿔야 합니다.
- **경유지 최적화는 한 번에 최대 `TMAP_ROUTE_OPT_SIZE`곳**까지 계산됩니다(기본 20곳).
  담당자 한 명이 이보다 많이 배송한다면 지역/시간대를 나눠 여러 번 요청하면 됩니다.
- "예상 도착시간"은 TMap이 계산한 **총 소요시간을 정류지 수만큼 균등 배분한 근사치**입니다.
  (TMap 응답에 정류지별 구간 시간이 별도로 오지 않아, 정확한 시간표가 아닌 참고용입니다.)
- 배송지별 "TMap으로 열기" 버튼은 **한 곳씩** TMap 앱 내비게이션으로 연결합니다.
  TMap 앱 URL scheme은 여러 경유지를 한 번에 넘기는 공식 방법이 공개되어 있지 않아,
  기사님이 한 곳 도착 후 다음 곳 링크를 누르는 방식으로 설계했습니다.
- 응답 파싱은 openapi.sk.com의 공식 문서(Request/Response 상세 설명)를 직접 확인하고 그대로
  맞춰 구현했습니다. 그래도 실제 appKey로 첫 연동 시 결과가 이상하면 `backend/.env`에
  `DEBUG_TMAP=1`을 추가해보세요 — 콘솔에 원본 응답이 그대로 출력되니, 그 로그를 보고
  `backend/src/services/tmapClient.ts`의 파싱 부분만 조정하면 됩니다.
- **TMap JS 지도 스크립트는 반드시 `frontend/index.html`의 정적 `<script>` 태그로만
  로드해야 합니다.** React 컴포넌트 안에서 `document.createElement('script')`로 동적
  삽입하면(흔히 쓰는 방법인데도) 화면이 멈춘 것처럼 보이면서 콘솔에
  `e.LatLng is not a constructor` 에러가 납니다 — TMap SDK가 내부적으로
  `document.write()`로 하위 스크립트를 불러오는데, 브라우저가 "비동기로 삽입된
  외부 스크립트에서의 document.write"를 막아버리기 때문입니다. 이미 고쳐져 있으니
  건드릴 일은 없겠지만, 혹시 지도 관련 코드를 손보다 이 에러가 다시 보이면 원인이
  바로 이겁니다.
